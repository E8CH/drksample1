# UX Design Specification — 셀프스토리지 브랜드 입지분석 관리자 웹 서비스 (POC)

**Author:** HEMICOLON
**Date:** 2026-06-12

---

## Executive Summary

셀프스토리지 브랜드 본사 담당자가 신규 부동산 물건의 주소를 입력하면 수익 시뮬레이션 결과와 1페이지 제안서를 즉시 받는 관리자 웹 POC 샘플의 UX 설계 문서다.

핵심 경험은 단 하나 — **"주소를 입력하고 버튼을 누르면 지도에 핀이 꽂히고 수익 결과가 나타난다."** 이 순간이 시연의 전부이며, 모든 UX 결정은 이 경험을 최대화하는 방향으로 설계된다.

디자인 레퍼런스는 다락(Dalock) 브랜드 자체 서비스(지점 탐색 화면, 온보딩 모달)로 확정되었다. shadcn/ui + TailwindCSS + Recharts + react-kakao-maps-sdk 기술 스택에 다락 블루(#2563EB) 컬러를 적용한다.

## 1. 프로젝트 이해

### 프로젝트 비전
셀프스토리지 브랜드가 신규 부동산 물건을 검토할 때, 담당자의 감에 의존하던 입지 판단을 데이터 기반으로 전환한다. 본 샘플은 AX 프로젝트 제안서에 첨부하여 "이런 시스템이 실제로 가능하다"는 것을 시연하는 POC다.

### 대상 사용자
**본사 담당자** — 신규 지점 개설 및 창업 제안 담당 실무자. 현재 네이버부동산 + Excel로 수익을 수동 계산 중. 데스크탑 환경, 일반 업무 수준의 기술 친숙도.

### 핵심 UX 과제
- 입력 폼 + 카카오맵 + 수치 결과 + 차트를 한 화면에 표현
- 제안서 팝업이 실제 보고서 수준으로 보여야 시연 설득력 확보
- 시연용이므로 첫인상 자체가 임팩트여야 함

### 디자인 기회
- 주소 입력 후 지도에 핀이 꽂히는 순간 → WOW 포인트
- 판정 배지(추천/검토필요/비추천) 색상 → 직관적 결과 전달
- 제안서 팝업 → 종이 보고서보다 세련된 디지털 서식

## 2. 핵심 사용자 경험

### 정의적 경험
> "주소를 입력하고 버튼을 누르면 — 지도에 핀이 꽂히고 수익 결과가 나타난다"

### 플랫폼
데스크탑 웹 우선 (1280px+), 마우스/키보드, 오프라인 불필요

### 경험 메커니즘

```
① 빈 폼 + 수도권 기본 지도 화면
       ↓ 주소 입력 시
② 지도가 해당 위치로 자동 이동 (실시간 미리보기)
       ↓ "시뮬레이션 실행" 클릭
③ 로딩 (1~3초) — "분석 중..." 스피너
       ↓
④ ★ 핀 등장 + ● 인근 지점 핀 페이드인
   오른쪽 결과 카드 슬라이드인
       ↓
⑤ 판정 배지 강조 + "제안서 출력" 버튼 활성화
       ↓ 버튼 클릭
⑥ 모달 팝업 — 제안서 미리보기 + PDF 저장
```

### 경험 원칙

1. **결과가 먼저** — 입력하면 즉각 시각 반응, 기다리게 하지 않는다
2. **지도가 중심** — 숫자는 지도 위에서 맥락을 갖는다
3. **보고서 품질** — 팝업은 그대로 출력해도 부끄럽지 않은 수준
4. **시연 무결성** — 담당자 앞에서 단 한 번의 끊김도 없어야 한다

### 시연의 결정적 순간

1. 주소 입력 → 지도에 ★ 핀이 꽂히고 ● 인근 지점들이 나타나는 순간
2. 팝업이 열리며 도표와 판정 배지가 보이는 순간 — "이게 제안서로 나온다고?"
3. PDF 파일이 깔끔하게 저장되는 순간

## 3. 감성 반응 설계

### 감성 여정

| 순간 | 목표 감성 |
|------|-----------|
| 첫 화면 접속 | **신뢰** — "전문적이고 깔끔하다" |
| 주소 입력 → 지도 핀 표시 | **놀라움** — "오, 바로 나오네" |
| 수치 + 차트 결과 화면 | **확신** — "데이터가 이렇게 정리되다니" |
| 제안서 팝업 오픈 | **실용감** — "이거 지금 당장 써도 되겠는데" |
| PDF 저장 완료 | **결정** — "이 프로젝트 해봐야겠다" |

**핵심 감성:** 신뢰 + 확신 — "이 시스템은 실제로 작동한다"

### 반드시 피해야 할 감성

- **혼란** → 화면에 정보가 너무 많으면 안 됨
- **의심** → 수치가 작위적으로 보이면 안 됨 (현실감 있는 데이터 필수)
- **불안** → 로딩이 느리거나 에러 발생 시 시연 전체가 무너짐

### 감성 → UX 설계 연결

| 감성 | UX 구현 |
|------|---------|
| 신뢰 | 여백, 정렬, 일관된 타이포그래피 |
| 놀라움 | 지도 핀 등장 페이드인 애니메이션 (0.3s) |
| 확신 | 판정 배지를 화면에서 가장 눈에 띄게 배치 |
| 실용감 | 제안서 팝업 A4 비율, PDF 버튼 상단 배치 |

## 4. UX 패턴 분석 & 영감

### 레퍼런스: 다락(Dalock) 자체 서비스

**참고 화면 1 — 지점 탐색 화면:**
- 좌측 패널(리스트) + 우측 카카오맵 분할 구조
- 흰 배경, 카드에 연한 그림자
- 파란색(#2B7FFF 계열) 강조, 오렌지 배지(할인/추천)

**참고 화면 2 — 모달 팝업:**
- 흰 배경 + 상단 파란 진행바
- 아이콘 + 텍스트 카드, 라운드 코너
- 하단 고정 CTA 버튼

### 적용 패턴

| 패턴 | 적용 위치 |
|------|-----------|
| 좌측 폼 + 우측 지도 분할 레이아웃 | Page 1 시뮬레이션 화면 |
| 파란색 계열 브랜드 컬러 + 흰 배경 | 전체 컬러 시스템 |
| 흰 모달 + 상단 강조선 + 하단 CTA | 제안서 팝업 |
| 라운드 카드 + 연한 그림자 | 결과 수치 카드 |
| 컬러 배지 | 추천/검토필요/비추천 판정 |

### 피할 패턴

- 정보 과밀 (좌측 패널은 심플하게 유지)
- 지도를 배경으로만 사용 (핀과 인터랙션 필수)

## 5. 디자인 시스템 파운데이션

**선택: shadcn/ui + TailwindCSS**

| 기준 | 이유 |
|------|------|
| Next.js 공식 호환 | 별도 설정 없이 즉시 사용 |

- `Recharts` — 비교 차트 (shadcn/ui 차트 통합)
- `react-kakao-maps-sdk` — 카카오맵 React 래퍼
- `html2canvas` + `jsPDF` — PDF 출력

## 8. 사용자 여정 플로우

### UJ-1 — 수익 시뮬레이션 + 제안서 출력

```
로그인 → 입지분석 페이지(빈 폼+기본지도)
→ 주소+조건 입력 → [필수항목 미입력 시 버튼 비활성]
→ "시뮬레이션 실행" 클릭
→ 로딩 스피너 (1~3초)
→ [유사지점 5개 미만 시] amber 경고 배너 표시
→ 결과 화면 (★핀 + ●핀 페이드인 + 결과카드 슬라이드인)
→ 판정 배지 확인 → "제안서 출력" 클릭
→ 모달 팝업 (도표 + 차트 + 판정)
→ PDF 저장 → 완료
```

**에러 복구:** 유사 지점 부족 → 전체 평균으로 대체 + 배너 안내 → 계속 진행 가능

### UJ-2 — 게시판 조회

```
게시판 페이지(기본: 기준연월 내림차순, 50건/페이지)
→ 연도 필터 / 지점명 검색 / 컬럼 정렬 (URL 쿼리 파라미터 반영)
→ "전체 재생성" / "전체 삭제" → 확인 다이얼로그 → 실행
```

### 공통 플로우 패턴

| 패턴 | 적용 |
|------|------|
| 파괴적 액션 전 confirm 다이얼로그 | 삭제/재생성 버튼 |
| URL 쿼리 파라미터로 상태 유지 | 필터/정렬/페이지 |
| 에러는 배너로 비침습적 표시 | 유사 지점 부족 |
| 로딩 중 버튼 비활성 + 스피너 | 시뮬레이션 실행 |

| `KakaoMapView` | react-kakao-maps-sdk | ★핀 + ●핀 렌더링 |
| `SimulationResultCard` | shadcn Card | 수치 + 슬라이드인 애니메이션 |
| `VerdictBadge` | shadcn Badge | 추천(green)/검토필요(amber)/비추천(red) |
| `ComparisonBarChart` | Recharts | 유사 지점 비교 막대그래프 |
| `ProposalModal` | shadcn Dialog | A4 비율 제안서 미리보기 + PDF 버튼 |
| `ProposalDocument` | 순수 HTML/CSS | PDF 출력 최적화 레이아웃 |
| `BranchDataTable` | TanStack Table v8 | 서버사이드 정렬/필터/페이지네이션 |
| `TableToolbar` | shadcn 조합 | 필터 + 검색 + 재생성/삭제 버튼 |
| `GenerateProgressBar` | shadcn Progress | 데이터 생성 진행률 + Toast |

### 구현 우선순위

```
Phase 1 (시연 핵심):
  LocationInput → KakaoMapView → SimulationResultCard
  → VerdictBadge → ProposalModal → ProposalDocument

Phase 2 (게시판):
  BranchDataTable → TableToolbar → AlertDialog

Phase 3 (완성도):
  ComparisonBarChart → GenerateProgressBar → Toast
```

## 10. UX 일관성 패턴

### 버튼 계층

| 종류 | 스타일 | 사용처 |
|------|--------|--------|
| Primary | 파란 배경 + 흰 텍스트 | 시뮬레이션 실행, PDF 저장 |
| Secondary | 흰 배경 + 테두리 | 닫기, 취소 |
| Destructive | 흰 배경 + 빨간 테두리 | 전체 삭제 |
| Ghost | 텍스트만 | 페이지 네비게이션 |

### 피드백 패턴

| 상황 | 처리 |
|------|------|
| 시뮬레이션 로딩 | 버튼 비활성 + 인라인 스피너 + "분석 중..." |
| 유사 지점 부족 | 상단 amber 배너 (자동 유지) |
| 데이터 재생성 완료 | 우측 하단 green Toast (3초 자동 닫힘) |
| 필수 항목 미입력 | 필드 하단 빨간 텍스트 + 테두리 강조 |
| PDF 저장 완료 | Toast "파일이 저장되었습니다" |

### 폼 패턴

- 필수 항목: 레이블 우측 `*` 표시
- 검증: blur 시점에만 (입력 중 에러 표시 금지)
- 제출 버튼: 필수 항목 모두 입력 시에만 활성화

### 모달 패턴

- 일반 모달: ESC / 배경 클릭 → 닫기 가능
- 파괴적 액션(AlertDialog): ESC / 배경 클릭 → 닫기 불가
- 제안서 모달: 스크롤 가능, X 버튼으로만 닫기

### 빈 상태 & 로딩

| 상태 | 처리 |
|------|------|
| 게시판 데이터 없음 | "데이터가 없습니다. 전체 재생성 버튼을 눌러주세요." + 버튼 |
| 시뮬레이션 전 결과 영역 | "주소를 입력하고 시뮬레이션을 실행하세요" 안내 |
| 테이블 로딩 | 스켈레톤 UI (행 형태 유지) |

## 11. 반응형 & 접근성

### 반응형 전략

| 브레이크포인트 | 너비 | 레이아웃 |
|--------------|------|----------|
| Desktop (기본) | 1280px+ | 좌측 패널 380px 고정 + 우측 지도 flex |
| Laptop | 1024~1279px | 좌측 패널 320px + 단일 열 |
| Tablet | 768~1023px | 상하 분할 (폼 접이식 + 지도 하단) |
| Mobile | ~767px | PRD Non-Goals (스코프 외) |

**핵심 반응형 규칙:**
- 지도 최소 높이 400px 유지
- 제안서 모달 뷰포트 90% 이내
- 게시판 테이블 1024px 미만 가로 스크롤 허용

### 접근성 (WCAG AA)

- 텍스트 명도대비 4.5:1 이상 ✅
- 최소 터치 영역 44×44px ✅
- 키보드 탐색: Tab 순서 논리적, Enter 제출 가능
- 포커스 인디케이터: 파란 링 (shadcn 기본)
- 지도 영역: `aria-label="카카오맵 — 분석 위치 및 인근 지점 표시"`

### 개발자 구현 지침

```
- TailwindCSS 반응형 클래스 (lg: md: sm:)
- 지도 컨테이너: min-h-[400px] lg:flex-1
- 모달: max-w-[90vw] w-[680px]
- 시맨틱 HTML: form, button type="submit", fieldset/legend
- 비활성 버튼: disabled + aria-disabled="true"
- Pretendard 폰트: @font-face 또는 CDN
```
