# PRD: 셀프스토리지 브랜드 입지분석 관리자 웹 서비스 (POC 샘플)

## 0. 문서 목적

본 PRD는 셀프스토리지 브랜드 AX 프로젝트 제안서에 첨부할 샘플 시연 서비스의 요구사항을 정의한다. 수신자는 본사 담당자이며, 다운스트림 산출물(아키텍처, 에픽/스토리)을 작성하는 개발팀이 주요 독자다. 용어는 §3 Glossary에 정의된 표현을 그대로 사용한다. 기술 스택 근거는 별도 기술 리서치 문서(`planning-artifacts/research/technical-selfstorage-fullstack-tech-research-2026-06-12.md`)를 참조한다.

---

## 1. Vision

셀프스토리지 브랜드가 신규 부동산 물건을 검토할 때, 담당자의 경험과 감에 의존하던 입지 판단을 데이터 기반으로 전환한다. 지점 주소와 부동산 조건을 입력하면 브랜드 기존 지점들의 실적 데이터를 기반으로 수익성을 시뮬레이션하고, 결과를 1페이지 제안서로 즉시 출력한다.

본 서비스는 AX 프로젝트 본 개발 착수 이전에 시스템의 가능성을 시연하기 위한 POC 샘플이다. 본사 담당자가 시연을 통해 "이런 시스템이 실제로 가능하다"는 것을 직접 체감하고, 프로젝트 도입 의사결정의 근거로 삼을 수 있도록 한다.

---

## 2. 대상 사용자

### 2.1 Primary Persona
**본사 담당자** — 셀프스토리지 브랜드 본사에서 신규 지점 개설 및 창업 제안을 담당하는 실무자. 현재는 네이버부동산에서 매물을 탐색하고 로드뷰로 입지를 확인하는 방식에 의존한다. 수익성 판단 근거 자료가 부족해 창업 제안 시 설득력이 떨어지는 문제를 안고 있다.

### 2.2 Jobs To Be Done
- 특정 부동산 물건이 브랜드 운영에 적합한지 빠르게 판단하고 싶다
- 창업 제안 시 수익성 근거 자료를 자동으로 만들고 싶다
- 기존 지점들의 실적을 한눈에 파악하고 싶다

### 2.3 Non-Users (v1)
- 가맹점주 및 예비창업자 (직접 접근 불가)
- 외부 고객 / 일반인

### 2.4 핵심 사용자 여정

- **UJ-1. 담당자가 신규 매물의 수익성을 시뮬레이션한다.**
  - **Persona + context:** 본사 담당자, 네이버부동산에서 관심 매물을 발견한 직후
  - **Entry state:** 로그인 완료, 입지분석 시뮬레이션 페이지
  - **Path:** ① 주소 및 부동산 조건 입력 → ② "시뮬레이션 실행" 클릭 → ③ 지도 + 수익 결과 확인 → ④ "제안서 출력" 클릭 → ⑤ 팝업에서 1페이지 제안서 확인 → ⑥ PDF 다운로드
  - **Climax:** 1페이지 보고서 형식의 제안서가 즉시 생성되어 바로 활용 가능함을 확인
  - **Resolution:** PDF 저장 후 제안 자료로 활용

- **UJ-2. 담당자가 기존 지점 실적을 조회한다.**
  - **Persona + context:** 본사 담당자, 지역별 실적 현황 파악이 필요한 상황
  - **Entry state:** 로그인 완료, 수익분석표 게시판 페이지
  - **Path:** ① 기간(연도) 필터 선택 → ② 컬럼 클릭으로 정렬 → ③ 원하는 지점 데이터 확인
  - **Climax:** 10년치 데이터를 자유롭게 정렬/필터하며 인사이트 도출
  - **Resolution:** 필요 시 특정 조건으로 재정렬하여 계속 탐색

## 3. Glossary

- **지점** — 브랜드가 운영 중인 개별 셀프스토리지 매장. 본 POC에서는 수도권 가상 데이터로 구성됨.
- **수익 시뮬레이션** — 입력된 부동산 조건과 기존 지점 실적 데이터를 비교 분석하여 예상 매출·점유율·순수익을 추정하는 연산.
- **수익분석 제안서** — 시뮬레이션 결과를 브랜드 서식으로 1페이지에 정리한 보고서. 화면 미리보기 및 PDF 다운로드 제공.
- **점유율** — 지점의 전체 보관 공간 중 실제 이용 중인 비율 (%).
- **순수익** — 월 매출에서 임대료·전기세·운영비를 차감한 값.
- **입지 조건** — 부동산 물건의 주소, 면적, 임대료, 관리비, 건축물용도, EV충전 유무, 주차 가능 대수의 집합.
- **유사 지점** — 입력된 입지 조건과 면적·임대료·지역 기준으로 유사도가 높은 기존 가상 지점군.
- **지도 데이터 프로바이더** — 지도 렌더링 및 지오코딩을 담당하는 외부 API. v1은 카카오맵, v2+는 네이버 부동산 JSON API로 교체 가능하도록 추상화됨.

## 4. Features

### 4.1 입지분석 시뮬레이션

**Description:** 본사 담당자가 검토 중인 부동산 물건의 입지 조건을 직접 입력하면, 기존 가상 지점 데이터를 기반으로 수익 시뮬레이션을 실행하고 결과를 카카오맵과 함께 표시한다. 실현: UJ-1.

**Functional Requirements:**

#### FR-1: 입지 조건 입력 폼
관리자는 아래 항목을 입력하여 시뮬레이션을 요청할 수 있다.
- 주소 (텍스트)
- 면적 (㎡, 숫자)
- 월 임대료 (원, 숫자)
- 관리비 (원, 숫자)
- 건축물용도 (셀렉트박스)
- EV충전 가능 여부 (토글)
- 주차 가능 대수 (숫자)

**Consequences (testable):**
- 필수 항목(주소, 면적, 임대료) 미입력 시 제출 버튼 비활성화
- 제출 시 3초 이내에 결과 화면으로 전환

#### FR-2: 수익 시뮬레이션 연산
시스템은 입력된 입지 조건과 가장 유사한 기존 가상 지점군을 추출하여 예상 수익 지표를 산출한다.

**연산 방식 (현실 세계 모사):**
1. 면적(±30%), 임대료(±30%), 지역(시/구 단위)을 기준으로 유사 지점 추출
2. 유사 지점군의 월 매출·점유율·전기세·운영비 가중 평균 산출
3. EV충전·주차 유무에 따른 보정 계수 적용
4. 순수익 = 예상 월 매출 - 임대료 - 전기세(추정) - 운영비(추정)
5. 전체 지점 대비 백분위 산출 → 종합 판정 도출

**종합 판정 기준:**
- 순수익 상위 30% 이상 → **추천**
- 30~60% → **검토필요**
- 하위 40% 이하 → **비추천**

**Consequences (testable):**
- 유사 지점이 5개 미만인 경우 "유사 지점 데이터 부족 — 전체 평균으로 대체합니다" 안내 메시지 표시
- 결과에 예상 월 매출, 점유율, 순수익, 브랜드 평균 대비 백분위, 종합 판정이 모두 포함됨

#### FR-3: 결과 화면 표시
시뮬레이션 결과는 다음 레이아웃으로 표시된다.

- **상단**: 카카오맵 — 분석 대상 위치(★ 핀) + 인근 가상 지점(● 핀) 표시
- **하단 좌**: 입력한 입지 조건 요약
- **하단 우**: 시뮬레이션 결과 수치 + 브랜드 비교 차트(막대그래프) + 종합 판정 배지
- **하단 우 하단**: "제안서 출력" 버튼

**Consequences (testable):**
- 카카오맵에 분석 대상 위치 핀과 인근 지점 핀이 모두 표시됨
- 결과 수치(매출·점유율·순수익)와 차트가 동시에 렌더링됨

**Feature-specific NFRs:**
- 지오코딩(주소→좌표 변환)은 카카오 REST API를 통해 서버사이드에서 처리 (API 키 클라이언트 노출 금지)

### 4.2 수익분석 제안서 출력

**Description:** 시뮬레이션 결과를 바탕으로 브랜드 서식의 1페이지 보고서를 생성한다. "제안서 출력" 버튼 클릭 시 모달 팝업으로 미리보기가 표시되며, PDF 다운로드가 가능하다. 실현: UJ-1.

**Functional Requirements:**

#### FR-4: 제안서 팝업 표시
관리자가 "제안서 출력" 버튼을 클릭하면 2초 이내에 모달 팝업이 열린다.

**제안서 구성 요소:**
- 브랜드 로고 + 제목 + 출력 날짜
- 물건 기본 정보 (주소, 면적, 임대료, 관리비, 건축물용도, EV, 주차)
- 시뮬레이션 결과 도표 (예상 월 매출 / 점유율 / 순수익)
- 브랜드 비교 차트 (유사 지점 평균 대비 시각화)
- 종합 판정 배지 (추천 / 검토필요 / 비추천)

**Consequences (testable):**
- 팝업은 인쇄/PDF 출력에 최적화된 서식으로 렌더링됨 (A4 비율)
- 도표, 차트, 서식 구분선이 포함된 보고서 형식으로 표시됨

#### FR-5: PDF 다운로드
관리자는 팝업 내 "PDF 저장" 버튼으로 제안서를 PDF 파일로 다운로드할 수 있다.

**Consequences (testable):**
- 다운로드된 PDF는 제안서 레이아웃을 유지함
- 파일명: `수익분석제안서_{주소}_{날짜}.pdf` 형식

---

### 4.3 수익분석표 게시판

**Description:** 수도권 가상 지점들의 10년치 실적 데이터를 테이블로 표시한다. 정렬·필터·페이지네이션을 지원하며, 가상 데이터 전체를 재생성하거나 삭제할 수 있다. 실현: UJ-2.

**Functional Requirements:**

#### FR-6: 데이터 테이블 표시
관리자는 전체 지점의 수익 실적을 테이블로 조회할 수 있다.

**컬럼:** 지점명, 주소, 기준연월, 월 매출, 전기세, 운영비, 순수익, 점유율

**Consequences (testable):**
- 기본 정렬: 기준연월 내림차순
- 페이지당 50건 표시, 페이지네이션 제공

#### FR-7: 정렬 및 필터
관리자는 컬럼 헤더 클릭으로 정렬하고, 지점명·연도로 필터할 수 있다.

**Consequences (testable):**
- 컬럼 클릭 시 오름/내림차순 토글
- 연도 필터 선택 시 해당 연도 데이터만 표시
- 필터·정렬 상태가 URL 쿼리 파라미터에 반영되어 공유 가능

#### FR-8: 가상 데이터 생성 및 삭제
관리자는 전체 가상 데이터를 재생성하거나 삭제할 수 있다.

**Consequences (testable):**
- "전체 재생성" 버튼 클릭 → 확인 다이얼로그 → 30초 이내 완료
- "전체 삭제" 버튼 클릭 → 확인 다이얼로그 → 데이터 전체 삭제
- 재생성 데이터: 수도권 가상 지점 기준, 2016~2025년 10년치

## 5. Non-Goals (명시적 제외)

- 실제 네이버/카카오 부동산 매물 데이터 연동 (모든 수치는 가상 데이터)
- 지도에서 직접 위치를 클릭하여 입력하는 방식 (v2 — 추상화 구조는 v1에 반영)
- 네이버 부동산 JSON API 연동 (v2+ — 프로바이더 교체 가능한 구조만 v1에 반영)
- 가맹점주 / 외부 사용자 접근 권한
- 실시간 매물 알림 기능
- 모바일 앱 (반응형 웹이나 앱 배포는 제외)
- 사용자 권한 분리 / 멀티 계정 관리
- 실제 브랜드 내부 데이터 연동 (모든 수치는 가상)

## 6. MVP Scope

### 6.1 In Scope
- **Page 1**: 입지 조건 입력 폼 + 카카오맵 + 시뮬레이션 결과 + 제안서 팝업 (PDF 포함)
- **Page 2**: 수익분석표 게시판 (정렬/필터/페이지네이션 + 데이터 생성/삭제)
- 단순 로그인 (admin 계정 1개, 하드코딩)
- 수도권 가상 지점 데이터 (10년치, 재생성 가능)
- Railway 배포 (Hobby 플랜)

### 6.2 Out of Scope for MVP
- 지도에서 위치 직접 선택 입력 (v2 — 구조는 v1에 반영)
- 네이버 부동산 API 연동 (v2+ — 프로바이더 추상화 구조는 v1에 반영)
- 실 데이터 연동 (별도 프로젝트 착수 후)
- 제안서 이메일 발송 기능 [`NOTE FOR PM`: 시연 후 요청 시 v1.1로 빠르게 추가 가능]

## 7. 성공 지표

**Primary**
- **SM-1**: 주소 입력 → 시뮬레이션 결과 화면 전환 3초 이내. FR-1, FR-2, FR-3 검증.
- **SM-2**: "제안서 출력" 클릭 → 팝업 표시 2초 이내. FR-4 검증.
- **SM-3**: 제안서 팝업이 도표·차트·서식 구분선을 포함한 보고서 형식으로 렌더링됨. FR-4 검증.
- **SM-4**: PDF 다운로드 시 레이아웃이 유지됨. FR-5 검증.

**Secondary**
- **SM-5**: 전체 데이터 재생성 30초 이내 완료. FR-8 검증.
- **SM-6**: 시연 시 UJ-1 핵심 플로우(입력→결과→제안서→PDF) 끊김 없이 동작.

**Counter-metrics (최적화 금지)**
- **SM-C1**: 제안서 로딩 속도를 위해 서식·차트를 단순화하지 말 것 — SM-3 품질이 SM-2 속도보다 우선.

## 8. Cross-Cutting NFRs

- **플랫폼**: 반응형 웹, 데스크탑 기준 설계 (1280px 이상)
- **보안**: 카카오맵/공공데이터 API 키는 서버사이드에서만 처리, 프론트 노출 금지
