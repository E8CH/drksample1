아래 기능을 포함한 크로스 플랫폼 서비스의 핵심 기능 샘플 구현을 하려고해.
먼저 POC 이전 단계의 최소 기능만 구현하려고해.
주로 상점의 상권분석 연동이 주 내용인거 같아.

요구사항 내용은 다음과 같아.

1. (현황 및 문제점) 
 ㅇ 해당 부동산 물건의 입지에서 미니창고 브랜드에 대한 수요가 어느정도일지에 대한 판단이 개인의 감과 인근지점 점유율 등 단순한 정보에 의존하고 있음
 ㅇ 창업 제안 시, 해당 지점 오픈 시 영업이 잘 될거라는 근거 자료가 부재. (일반적인 점유율/수익에 대한 지표만 제공중)
 ㅇ 본사에서 직영지점을 만들기 위해 셀프스토리지에 적합한 물건을 찾는 과정이 비효율적임
  - 네이버부동산 등 플랫폼에서 지역선정 → 필터지정 (임대료, 면적, 월세 등) → 로드뷰를 통한 입지분석  
  - 공실기간, 주차, 내부접근성 등 브랜드 운영에 필수적인 요소는 파악이 어려움
  - 기존에 올라와 있는 물건을 필터링 하는 수준으로 조건이 좋은 물건을 선제적으로 확보하기 어려운 상황

2. (과제주제 제안) 현재 본부에서 필요하다고 느끼는 AX 프로젝트로, PoC 단계에서 가능한 범위 등을 고려해 제안 부탁드립니다.
 ㅇ 필수/  (브랜드형 입지분석) 브랜드에서 운영중인 220개 지점의 점유율, 수익분석표, 부동산 조건(임대료, 관리비, EV, 입지조건 등), 인근 거주인구/소득수준, 인근 아파트 준공년도/세대창고 유무 등을 활용해 해당 부동산 물건 브랜드 수익성 시뮬레이션
 ㅇ 검토필요 / (수익제안서 출력) 해당 시뮬레이션을 기반으로 수익분석 제안서 1page 를 자동으로 출력
 ㅇ 검토필요 / (브랜드형 부동산 물건 추천) 브랜드을 운영하기 적합한 부동산 물건이 신규로 올라왔을 때 자동으로 물건 탐색 후 알림

3. (활용 필요 데이터)
 ㅇ (내부) 지점 주소, 부동산 조건(면적, 임대료, 관리비, 건축물용도), 지점별 점유율 추이, 지점별 이용고객 주소, 지점별 수익분석표(매출, 전기세, 운영비 등), EV유무, 주차 등
 ㅇ (외부) 거주/직장인구, 소득데이터, 카드매출데이터, 아파트 준공년도 등 (※ 이부분은 제안주시거나 함께 디벨롭했으면 좋겠습니다)

위 요구사항에서 3번에 해당하는 내용은 추론해서 가상으로 1000건정도를 만들어줘야 해


- 기능 범위
  - 관리자 : 위 요구사항에서 2번에 해당하는걸 간략하게 만들어줘야 함
  - 주로 지점별 수익분석표(매출, 전기세, 운영비 등), 지점별 점유율 추이를 주요 결과로 뽑아내야 함
  - 10년치 데이터에 대해 소팅해서 볼 수 있는 게시판 형식의 페이지도 필요.
  - 속도가 느리지 않다면 10년치 데이터를 랜덤으로 만드는 버튼, 삭제 버튼 필요

- 시연에 사용하는 기술 스택
  - 1. 관리자용 반응형 웹 (Next.js)
  - 2. 통합 API (FastAPI)
  - 3. DB (Railway의 PostgreSQL)
  - 4. 배포 (Railway : 프론트엔드, 백엔드, PostgreSQL)

-DB 설계
지점 : 지점명(PK), 지점 주소, 부동산 조건(면적, 임대료, 관리비, 건축물용도), 전기차 충전가능유무, 주차가능 대수
운영 : 지점명(FK), 1달 전기세, 1달 운영비
회원 : 회원이메일(PK), 이름, 연락처, 주소
매출 : 지점명(FK), 지점별 이용고객(회원이메일FK) 주소, 1일 매출


-조건
3페이지를 넘지 않는 샘플식의 서비스일것
데이터를 만들때는 10년치 데이터로 가정할 것
브랜드 지점 또는 부동산의 범위는 대한민국 수도권으로 지정



- 참고 사항
지도에 대한 정보를 받는 것은 별도의 외부 API를 통해서 받을 것으로 예상(JSON)
이에 해당하는 JSON의 요구 항목도 결정이 되어야 함
따라서 API를 직접 만들기보다 이부분은 샘플정도로만 자체제작 하고, 나중에 외부 API가 완성되면 이걸 바꿔서 적용할 수 있어야 함
